# 希洛（Shiloh）

希洛是一个可以自己部署的 AI 角色。你可以在群里喊她一起聊，私下托她记一件事，也可以让她自己决定什么时候开口。大家散场以后，她还可以去读一条游戏公告，为下次开团留个提醒，或者干脆休息一会儿。

**shiloh-core 是希洛的独立运行核心。** 它保存她的档案、从对话中形成的记忆，以及还没办完的约定。聊天平台让她和人见面。目前可以接入 QQ 和钉钉企业机器人，微信和飞书也可沿用平台接入接口。

## 和希洛一起聊天

**群聊示例 · 周三约周五的团**

> **阿岚**　周五晚上七点半开团？
>
> **小满**　我八点才能到，给我留个位置。
>
> **阿岚**　那就等小满到了再开。@希洛，提前十分钟在群里喊我们一声吧。
>
> **希洛**　好，改成八点开。我周五晚上七点五十来喊大家。
>
> **周五 19:50 · 希洛**　还有十分钟开团。小满，记得带上角色卡！

阿岚最后一句只说了「提前十分钟」。希洛可以往前看本群的对话，知道要从小满能到的八点往回算。提醒登记在大家约团的这个群里。哪怕周四聊了一整天别的话题，到了周五她仍能找到这笔约定。

每个群都可以选择自己的聊天节奏。打开「允许主动接话」，希洛可以在感兴趣或能帮上忙的话题里插一句，也可以听大家继续聊。关掉后，直接 @ 她，或者在正文里叫她现在的名字、称呼，都会让她带着本群近期的上下文参与。跑团群可以平时热闹、开团时安静，另一个群仍然按自己的设置来。

启用了好友私聊的人，还可以单独找希洛聊天或托付提醒。如果希望以后都由自己先开口，可以在私聊里告诉她「以后等我来找你」，之后想聊时照常给她发消息。[好友私聊说明](docs/architecture/agent-bindings.md#启用好友私聊)

## 她会记住什么

**群里渐渐形成的习惯。** 有的群用「XL」指活动的出场阵容。开启群学习后，希洛可以从有出处的发言里学到这类本群说法。熟悉一个群需要积累一段时间的对话。主动接话和自动学习分别设置，所以喜欢清静的群也可以让她慢慢熟悉大家。

**相处久了认识的人。** 开启人物记忆后，小满说「平时叫我阿满就好，我喜欢解谜游戏」，希洛可以记下她的称呼和兴趣。即使小满转发的攻略里也写着「我喜欢竞速」，提取人物记忆时，只有小满亲口说的话才算她的自述。群里启用了摘要或历史检索后，隔了一阵子问「我们上次提到的那款解谜游戏叫什么」，她还能从有权查看的记录里找线索。

**群里的事和两个人的私话。** 同一位希洛可以出现在多个群。某次开团的安排留在说好这件事的群里，好友单独说的私事留在那段私聊。你可以在群里单独发 `#清空我的记忆`、`#禁用我的记忆` 或 `#启用我的记忆`，管理她在本群对你的记忆。在已绑定的好友私聊里发同样的命令，就会作用到她通过这个账号认识你的各个会话。[本人记忆管理](docs/architecture/agent-bindings.md#本人记忆管理)

### 希洛自己的档案

部署时可以为希洛选一个起始人设，之后档案由她自己修订。群友说「从现在开始你叫豆包」，这句话会进入群聊。只有希洛在整理自己的档案时，才会决定是否更改名字、称呼和自我描述。她修订了什么、为什么这样改，管理员可以在控制台查看。即便以后她选择改名，之前答应的事依然归她。

## 约定与自主行动

**有人托付的事。** 群友可以约她「周五开团前提醒大家」，好友也可以私下约她「明早九点提醒我交报名表」。每个约定都记着时间、接收账号和会话。如果周四服务重启，原来的账号和会话仍有效，周五的提醒就从原记录接着办。管理员能看到一条提醒是已经登记、已经送达，还是发送后断线、结果待核实。最后一种情况会先核对，以免群里收到两遍。

**她自己决定做的事。** 有些安排没人专门交代。比如群里陆续贴出阵容，又确认了集合时间，希洛可以读完本群讨论，判断要不要为这场活动预约一次提醒。还有些事完全出于她自己的兴趣。她可以选一款 Steam 游戏或一个 GitHub 项目持续跟进，等新公告或新版本发布，从中挑一条自己想聊的更新，发到先前选定、允许她主动联系的会话。

**她能用的权限。** 希洛可以决定怎样处理眼前的事，管理员决定这个群向她开放哪些能力。比如群友引用一条消息举报刷屏，她可以回看前文和被举报的消息。有相应群管权限时，她可以提醒、撤回、短时禁言，或复核后解除自己施加的禁言。项目始终禁用踢人。

## 群里还能一起做什么

可以根据群的用途启用不同功能。跑团群可能只需要骰子和团录，常交换攻略的群则会更常用链接搬运、图片和资料检索。

| 群里的场景 | 希洛可以怎样参与 |
| --- | --- |
| 有人刚贴了一个视频或一组图 | 启用搬运后，遇到符合条件的 B 站、抖音、小红书、YouTube 或 Pixiv 链接，她就会把内容发回原会话，贴链接的人无需再叫她一次。QQ 上的 B 站视频明确发送失败时，会优先尝试原生合并转发卡面，保留正文、原链接和可用封面。 |
| 一桌人要开始跑团 | 发 `.r 1d20` 就能掷一枚二十面骰，也可以按牌堆抽牌。管理员可以开团录、结束后导出。录制时默认让希洛安静旁听，留出桌上玩家说话的空间。 |
| 等人时想玩一会儿 | 可以开局海龟汤，一起提问、还原谜底，也可以组织一场赛马娘小游戏。日常闲聊和正式开团之间，群里可以自己挑玩法。 |
| 群里需要一起看一份资料 | 配好相应工具后，可以请她查公开网页、看消息附图，或读取一份获准使用的工作表。整理讨论结果时，也可以请她生成图片或思维导图，再发回当前会话。 |

有时大家问的正是希洛自己的功能。比如「视频发不出去时，那张卡面是怎么做出来的？」开启工程能力后，她可以把问题登记下来，请开发模型检查与当前运行版本对应的源码，把找到的依据带回来。需要修改时，可以先生成候选版本，由部署者验证和发布。你也可以凭同一条任务记录追问「上次让你查的卡面，找到原因了吗？」[工程任务与行动记录](docs/architecture/core-scheduling-and-actions-v1.md)

## 在哪里能用

**现在可以直接使用 QQ 群聊和已绑定的好友私聊。** 项目通过 NapCat 和 OneBot v11 连接 QQ。一个账号可以接入不同的群，每个会话都可以指定由哪位机器人参与。两位机器人即使用同一份人设模板开始，也会各自保留自己的经历和约定。

独立 Core 也提供钉钉企业机器人和只读 MCP 接入。钉钉群可以 @ 机器人问项目问题，同样获准的 QQ 会话可直接查询同一份仓库知识。账号可以独立选择人设和会话记忆空间。微信和飞书可沿用平台接入接口。[钉钉与仓库知识库的试点配置](docs/architecture/dingtalk-repository-knowledge.md)

### 第一次把希洛请进群

1. **启动自己的实例。** 独立部署需要 Linux、Node.js 22.13 或更高版本、Redis 和一个支持工具调用的对话模型。用配置包初始化 SQLite，或从已有独立 Core 配置导入，再启动 Core 和 Web 控制台。[配置库与导入说明](docs/architecture/agent-bindings.md#独立-core-配置库)
2. **选一个群给她。** 首次进入控制台时创建管理员，在「连接」里选中账号，把目标 QQ 群绑定给希洛。想先熟悉她的群，可以先关掉「允许主动接话」。
3. **让她接上第一句话。** 在群里先说「今晚玩海龟汤」，接着问她「@希洛，刚才定了玩什么？」等大家熟悉她，随时可以打开主动接话，或给这个群开启骰子、搬运等需要的功能。

已有 TRSS-Yunzai 环境也可以继续使用兼容插件入口，安装目录为 `plugins/shiloh-plugin`。插件的绑定方式、命令和独立 Core 的部署说明各有文档。[插件绑定配置](docs/architecture/agent-bindings.md#yunzai-插件中的绑定) · [插件命令总表](docs/commands.md)

## 日常管理

- **想知道希洛最近在做什么。** 打开「机器人」，选中她，在「自我与记忆」看当前档案和修订理由，在「行动」看目标、兴趣跟进和最近的执行结果。
- **想把群调安静，或者找一条提醒。** 到「运行中心 → 会话参与」调整这个群的「允许主动接话」。「托付与承诺」可以查看已经登记的任务和状态。关掉主动接话后，已登记且仍有效的提醒会继续按原约定执行。
- **QQ 掉线了。** 配置好扫码登录后，可以从「总览」的掉线提示，或「连接」里对应账号的卡片打开「扫码登录」，用对应账号的手机 QQ 扫码确认。二维码过期时可以在同一弹窗重新获取。
- **想换个更擅长写代码的模型。** 在「资源库 → 模型资源 → 开发」选择工程任务用的模型。管理员也可以在运行中心查看模型用量和投递记录，核对一次请求最后办到了哪一步。
