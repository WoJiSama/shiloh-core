# 系统代码设计审查与修复（2026-11-11）

## 范围与交付口径

用户要求从代码设计和完整业务流程检查已经实现的系统，并授权把发现的问题全部修复、可并行开发。本次沿消息进入、权限与路由、工具执行、持久状态、发送、后台管理追查普通对话、MCP、角色仿真、承诺、委托/语义记忆、媒体投递、控制台与游戏。结论依据调用链、状态所有权和故障复现；测试用于证伪和回归，不以通过数量代替设计审查。

实施起点为本地 `c08f8d0`，保留此前的角色一致性实验默认关闭与已有边界；预存未跟踪文档 `docs/llbot-onebot-absorption-2026-11-10.md` 未纳入本次修复。交付范围是本地代码、验证与本文档，发布状态沿用历史记录，不把此次修改宣称为已上线。

## 验证记录

验证以隔离Redis/文件目录、脚本模型、假平台回执及本地HTTP进行。此前复现已覆盖原实现的数据丢失、重复副作用、观点复活、错误归因和控制台退出；新增回归覆盖修复不变量。最终整合门禁结果见本节完成记录及 `reports/system-design-review-2026-11-11/`。

最终 `npm run verify:phase` 退出码为0，覆盖后端/测试严格类型、模块边界、正式构建、后端行为、控制台类型/行为/构建及迁移校验。后端3365项通过、0失败、2项既有模板截图检查因缺Chromium跳过；控制台17个文件、73项全部通过。上一轮失败的完整56事件重复回放已通过，新增的修订回执/观察器隔离/工作器未知结果5项整合检查也全部通过。

`verifyBackend(undefined, { source: true })` 确认558项源码清单与1659项编译产物完全匹配；源码/产物清单摘要见 `backend-artifact-verification.json`。入口脚本语法和 `git diff --check` 通过，预存未跟踪文档的SHA256保持不变，配置及业务数据文件没有本批修改。总证据索引为 `verification.json`，最终原始门禁为 `verify-phase.log`。

验证过程保留了失败证据：`unknown-worker-red.log`、`unknown-worker-through-seq-red.log` 和 `worker-artifact-save-red.log` 分别证明未知说明丢失、标读覆盖说明、作品保存失败后重复执行；修复后同案例见 `unknown-worker-green.log`。首轮整合门禁发现新缺陷后主动停止，日志单列为 `verify-phase-before-final-fix.log`，不计为完成。

正式整合还发现两个衔接问题，见 `verify-phase-integration-failures.log`：旧self断言错误要求全局共享，已按当前bot/人设/群作用域改正；来源修订正确清空旧上下文后，回放器漏取最后的收尾回执，已通过只读工具结果观察端口采集实际回执，不恢复过期上下文、不推造执行结果。缺回执原始场景见 `opinion-revision-red-results.json`。中途一次定向运行因源码已修改但尚未重建而被manifest检查拒绝，见 `opinion-revision-observer-stale-build.log`，该记录不算业务故障复现。

并发审查的临时转译目录另因缺少构建manifest或宿主适配文件产生25项环境失败，原始记录见 `character-private-environment-incomplete.log`，不把该次结果记为完整通过；最终结论使用正式工作区门禁。既有两项模板截图检查在此环境缺Chromium时跳过，不能据工程门禁宣称截图验收完成。

## 实际限制与后续验收

- 外部发送/工具动作与本地Redis不能组成跨系统事务；unknown表示需要核实，不能证明动作未发生。取消阻止后续动作，已交给平台/OS/上游的动作无法保证撤回。
- 承诺终态详情保留24小时，失败日志最多20条；这是运行恢复与告警，不是永久审计。
- 仿真仍假设单个执行进程、每群一个绑定bot；游戏占用同进程、按运行目录隔离，Uma文件事务支持同机多进程，不宣传多机协调。
- RAG只能补仍在归档保留期内的内容；每条保留原有400 code point上限。消息ID检查点证明正文已提交索引，不能替代召回质量验收。
- 纠错来源只证明哪些chunk曾注入该回合，不证明模型逐条引用；关联缓存重启失效时保守跳过。
- 本批未向QQ实发、未调用真实模型/外部工作器、未修改生产Redis；真实平台、模型效果与线上发布仍须独立验收。角色语义一致性实验继续默认关闭，既有阶段7的人审、真实跨天及实际工作器验收口径不变。
