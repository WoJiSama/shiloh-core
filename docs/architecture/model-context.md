# Core 模型上下文

Core 在实际发送 HTTP 请求之前，按选中的模型及渠道计算输入预算。系统提示、工具定义、工具参数、回执和会话资料都计入实际 JSON 请求体。日志记录 UTF-8 字节数、保守的 token 估算和供应商报告的实际用量。估算由同一后端已返回的用量向上校准。真实费用以供应商账单为准。

## 配置

独立宿主的 `agent-host.yaml` 可按供应商实际使用的模型名设置窗口、输出与推理预留和 HTTP 请求体上限。不同渠道使用同一模型名时，可以用 `渠道主机名/模型名` 优先匹配当前渠道。下列数字为示例。

```yaml
modelContext:
  your-chat-model:
    windowTokens: 32768
    reserveOutputTokens: 4096
    maxRequestBytes: 131072
```

未声明的托管模型使用 65,536 输入输出总预算、4,096 输出预留和 512 KiB 请求体上限。窗口另为估算误差保留至少 256 token。已有显式输出上限高于预留时，按较大的值预算。配置过窄导致必需上下文放不下时，模型调用以受控错误结束。

## 取舍与来源

- 处理直接问候时，群聊只提供普通发送和收尾工具，保留当前对话、角色设定和既有发送约束。提醒、文件、搜索等请求继续使用当前会话授权的工具。
- 系统协议和角色规则置于稳定前缀，当前时间、发言和资料在后面。工具定义按稳定顺序发送，缓存命中率由供应商实际报告。
- 预算压力下先省略风格参考、旧对话和可查回忆，再缩短唤醒资料和成功读取结果。当前发言、最近唤醒、当前话题的更正、活跃目标、行动回执和收尾规则保留。回退到文字模型时，工具资料仍带原调用编号和回执。
- 网页和搜索按明确来源保留相互独立的节选。同一来源和同一原始正文在本轮重复出现时，较早的结果指向后一次调用，同时保留各自回执。文件文本默认每页 4,000 个 Unicode 字符，按字符偏移分页。Excel 保留工作簿、工作表、列和完整命中块，区域截断时给出续读起始行。群史返回包含作者、时间、原消息 ID 和续页游标的 JSON。
- 群聊已读位置只沿连续且成功送进模型回合的消息前进。工具结果被截断、未进入成功调用或仍在同批待发送时保留未读。
- 含「上次」「之前」「最后定的」等接续信号的请求可按原会话读取近期耐久消息，保留更正作者、时间、消息 ID 与待确认的提问。匹配提醒从当前承诺账本读取，原消息、隐私水位、绑定及账本条目在用前复核。召回排除当前上下文已有的原消息 ID。

## 超限和长任务

供应商明确报告上下文超限或返回 413 时，适配层仅在还能缩小请求且必需内容仍放得下时，复核授权后发起一次较小的推理。适配层也识别 HTTP 200 中的结构化超限错误。413 按请求体过大记录。两次推理共用原回执，结果未知的动作继续凭原账本核实。

长工程任务先缩减旧的操作和结果，再重读核对源码片段。若仍需要压缩，最多发起一次无工具的工作记录总结。固定发布版本下的只读调查可按原任务编号从检查点续接，检查点记录轮次、源码位置和哈希、下一步及总结触发状态。重启后复核任务来源和原文，账本结算后清理检查点。修改候选的中断继续走现有的结果核实流程。

## 观测及验收

控制台「运行观测 → 模型上下文」按平台、会话类型、用途、模型和渠道汇总已授权日志的首轮、后续与每条轨迹累计用量。面板同时显示延迟 P50/P95、系统提示和工具定义体积、压缩节省字节数、超限次数、重复读取次数、缓存输入占比及可估价样本的金额。

离线回放通过实际运行入口调用本地模型和传输夹具。运行以下命令回归短群聊、多次读取、原群改期提醒、投递回执丢失、超限仅重试推理、只读工程调查续接，以及来源撤回和未读水位。

```powershell
npm run backend:build
node --test tests/modelExecution.test.js tests/agentSimulationDiagnostics.test.js tests/agentContextPaths.test.js tests/agentUnifiedChat.test.js tests/agentTextFailures.test.js tests/agentExcelTool.test.js tests/agentFileTextTool.test.js
npm run console:check
```
